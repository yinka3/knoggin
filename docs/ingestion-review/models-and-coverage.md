## Which model does what

| Job | Route visible in code | Rule |
| --- | --- | --- |
| Agent planning, replanning, final answer | Hosted `agent_model`, default `google/gemini-3-flash-preview` | Execution steps use `extraction_model` instead, unless the request context overrides the model (`server/src/core/agent/executor.py:225-250`; `server/src/common/schema/settings.py:169-175`). |
| Routine Context entity candidates | Known alias matching, then local GLiNER2.5 VP-01 (`fastino/gliner2.5-base-v1` for English; `fastino/gliner2.5-multi-v1` for multilingual) | Domain language selects the checkpoint; domain labels and descriptions constrain its schema (`server/src/core/ingestion/text_processor.py:208-355`; `server/src/core/ingestion/vp01.py:10-12,38-75`). |
| Optional candidate judgment | JEV `jev-1.13.0` | Identity, extraction, and classification modes default to disabled. Observe and active modes and per-window caps are explicit (`server/src/common/schema/jev.py:20-66`). |
| Entity merge maintenance | Agent tools `inspect_duplicate_entities`, `advise_entity_merge`, and `propose_entity_merge`, followed by a reviewed application merge | Inspection stays deterministic. The explicit advisor sends bounded candidate message/episode excerpts to configured `merge_model`, validates citations, and returns nonbinding advice. Proposal checks evidence membership and preview freshness before opening review (`server/src/core/knowledge/entity/merge_advisor.py`; `server/src/core/agent/tools/maintenance.py`). |
| Entity fallback and VP-02 relationships | Hosted `extraction_model`, default `google/gemini-2.5-flash-preview` | Entity fallback is targeted to gaps; VP-02 relationships use a structured call for impacted Context (`server/src/core/ingestion/text_processor.py:358-376,527-534`; `server/src/core/ingestion/relationship_extractor.py:159-190`). |
| Episode, Context update, conflict discovery | Hosted `extraction_model` by default | These call `generate_structured()` without `model=` (`server/src/core/knowledge/episodes/generator.py:110-134`; `server/src/core/knowledge/context/updater.py:444-449`; `server/src/core/knowledge/jobs/conflict_discovery_job.py:98-104`; `server/src/infrastructure/llm_client.py:519-545`). |
| Document parsing | Local Docling PDF layout/table/OCR models on CPU; Tesseract for images; deterministic text, notebook, CSV, and Tree-sitter code paths | Docling conversion is lazy and serialized, with remote services disabled (`server/src/core/knowledge/documents/extraction.py:384-440,707-743`). `server/scripts/prefetch_models.py` downloads Docling artifacts (`server/scripts/prefetch_models.py:59-74`). |
| Document embedding/search | Local embedding and reranker models | Runtime defaults are Stella 1.5B and BGE reranker large (`server/src/runtime/resources.py`; `server/src/core/knowledge/services/embedding_service.py`). They support indexing and retrieval. |

`merge_model` defaults to `google/gemini-2.5-pro` and is hot reloadable (`server/src/common/schema/settings.py`; `server/src/infrastructure/llm_client.py`). After the user approved the stored-evidence data flow, `advise_entity_merge` now passes `model=llm.merge_model` to `generate_structured()` for one selected pair. It sends at most two messages and two episode summaries per entity, with each text capped at 800 characters. The model cannot open or apply a review. Scheduled maintenance still runs deterministic preflight only (`server/src/core/knowledge/jobs/application_maintenance_scheduler.py`).

`LLMService.generate_structured()` uses Instructor/Pydantic output validation and owns validation retries so each provider attempt can be admitted to the spending ledger separately (`server/src/infrastructure/llm_client.py:519-604`). The model's output still passes application checks for handles, eligible blocks, domain labels, and persistence. Those checks verify shape and provenance membership; they do not prove that cited prose entails a proposed relationship (`server/src/core/ingestion/relationship_extractor.py:241-299`).

## Test evidence and limits

- Initial scan runs: **65** extraction unit tests, **50** Context/Knowledge stage and build-validation unit tests, and **21** `LLMService` unit tests passed. Current remediation rerun: **189 passed** across extraction, relationship, maintenance, domain, projection, Context/Knowledge, embedding, resource setup, and runtime configuration. These are focused test runs, not a coverage percentage. One dependency warning appeared.
- `test_llm_client.py:118-141` genuinely asserts that a structured call without a model override selects `extract-v1`. The advisor unit test now asserts the actual `merge_model` argument at the `generate_structured()` boundary, the bounded prompt content, and citation checks. It uses a fake model; no hosted merge request was made locally (`server/tests/unit/knowledge/test_entity_merge_advisor.py`).
- The tool test checks forwarding to the application service, while the advisor test checks the model call and confirms that it opens no review. The existing proposal test checks only review forwarding; confirmed merge application remains a separate path (`server/tests/unit/core/agent/test_conflict_reporting_contract.py`).
- The source-only entity tests assert that both a plausible paraphrase and an unrelated name leave no entity association. Invalid source quotes are rejected, and JEV makes no call for a source-only alias. The exact quote is kept only in the current build's unresolved issue; there is no durable review queue. The fixed merge shortlist has both a SQL-order unit assertion and a Postgres contract with a weak lower-ID pair competing against a higher-support later pair; the contract still needs a working Postgres fixture.
- The cached-model smoke now covers embedding and reranking; its real artifacts were not run locally after the NLI artifact was removed.
- PDF/DOCX and OCR format tests replace Docling conversion and Tesseract output with deterministic fakes (`server/tests/integration/ingestion/test_document_format_runtime.py:265-277`; `server/tests/contract/storage/test_document_format_indexing.py:218-229`). The release/dispatch model lane provisions Stella, BGE, and English VP-01 but does not execute a real Docling PDF conversion (`.github/workflows/server-tests.yml:219-288`). Thus a passing format or model lane does not establish that the PDF parser artifacts are present and usable.
- A missing Docling artifact now raises `DependencyError`, so the document indexer records a retryable `transient_dependency`; malformed content still records nonretryable `invalid_content`. The parser regression checks this classification boundary. Retries remain bounded, so installing the artifact after exhaustion still requires explicit reindex (`server/src/core/knowledge/documents/extraction.py`; `server/src/core/knowledge/documents/indexer.py`). See [general ingestion](general-ingestion.md).
- The VP-02 duplicate test repeats one identical two-block support tuple, so it cannot catch loss of two *independent* sufficient support groups or distinct observed labels (`server/tests/unit/core/ingestion/test_context_relationship_extractor.py:185-259`).
- The domain activation integration test checks capture and snapshot state but does not complete a semantic window after activation (`server/tests/integration/ingestion/test_project_semantic_postgres_flow.py:709-823`). The full integration file could not run here: **7 setup errors** occurred when its Postgres fixture timed out connecting to `127.0.0.1:5432`. No integration assertion ran.

The independent relationship-support persistence/retirement contract is written but has not run against Postgres. A same-revision clean projection rerender now has a unit regression. The highest remaining integration check is activation followed by a no-op Context update through Knowledge and the next window. A test that supplies a syntactically valid but unsupported VP-02 edge would document the current semantic trust boundary.

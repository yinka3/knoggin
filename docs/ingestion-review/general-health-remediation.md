# General ingestion and health remediation

Working plan, 2026-10-10. Source and persisted outcomes take priority over test names or old README text. The [general ingestion](general-ingestion.md), [health](health.md), and [intersection](general-health-intersections.md) scans hold the original evidence.

The [completion audit](remediation-completion-audit.md) records current status across all four reviewed layers, including later findings and verification limits.

## Implemented in this pass

1. **Concurrent same-path upload:** create-only publication uses a hard link from the completed temporary file, so the destination is created atomically and cannot replace a concurrent winner. A synchronized two-upload test checks that exactly one catalog row wins, its hash matches the surviving file, and no temporary file remains. Filesystems that do not support hard links will reject create-only upload; this needs deployment compatibility review.
2. **Failed/cancelled exchange maintenance blockage:** the maintenance pending-work count excludes these two outcomes, matching semantic admission. A real Postgres contract checks that they do not block a frontier, while an unclaimed valid exchange still blocks until it joins a completed window. The contract is written but not executed: the Docker daemon is unavailable locally.
3. **Terminal document-index health:** a scoped SQL count of failed documents with no retry flows through `DocumentIndexer` and `DocumentService` into background health. Health degrades and shows only the count, not the parser error. The parser-failure test now checks this producer-to-health boundary. The affected unit/integration suite passed 121 tests.
4. **Unavailable maintenance repair read:** engine health now degrades when the expected maintenance repair metric cannot be read, rather than treating an unavailable count as zero. The health suite passed 17 tests; the failure detail stays out of the public payload.
5. **Scheduler preflight failures:** consecutive job-check errors are recorded by job name with a fixed count cap and no exception text. Ingestion health degrades for a failing `project_semantic` check; a later successful check clears the signal. A real scheduler-to-health test and the affected scheduler/health suites passed 39 tests.
6. **Document upload cancellation and inline indexing failure:** file and catalog operations are shielded and settled before cancelled callers return; a completed insert is tombstoned before its owned file is removed. If the catalog rollback fails, bytes remain to preserve a live row's source. Once admission has saved a row, an inline indexing error is logged and the API returns that row's ID and current indexing status. Tests cancel both a delayed file worker and an in-flight catalog insert, assert no live orphan after reconciliation, and drive an invalid PDF through both single-upload and batch public ports. The affected document/API/filesystem suites passed 122 tests.
7. **Scheduler semantic timeout accounting:** a scheduler-imposed deadline calls the semantic processor only after cancellation unwinds. The processor records the active stage's timeout against the same durable window, stage, and attempt count. A stage that advanced before the callback is not charged; ordinary shutdown cancellation never invokes it. A provider-raised `TimeoutError` is now classified as a job failure, not as the scheduler deadline. The semantic/scheduler/health suites passed 36 tests, including backoff, exhaustion, and shutdown cancellation. The Postgres compare-and-set contract collects but cannot run without the database daemon.
8. **Claimed history in admission:** the reader now excludes already claimed exchanges in SQL instead of transferring their content and discarding it in Python. The session FIFO blockers that remain unclaimed are still returned. A real Postgres contract checks that a completed membership disappears while an editable head and later closed exchange remain; it collects but awaits the database daemon. The admission and maintenance unit suites passed 22 tests. Repeated full-prefix tokenization is still present; changing exact target-crossing semantics requires a benchmark and tokenizer-aware design.
9. **Unrelated work masking document indexing:** background health now looks for the document indexer's admission loop, local submission tasks, or project-scoped `document-index` work. A semantic job or Episode task alone cannot make a saved queued document look healthy. A real queued catalog row through `DocumentService` reaches degraded background health when its index loop is inactive. The health suites passed 20 tests; a prior healthy integration fixture had to be updated to supply the expected maintenance repair read.
10. **Due semantic window without a running job:** the scoped aggregate now counts runnable windows and measures time since their last durable stage change or retry due time. Ingestion health marks one delayed after two scheduler cadences (at least 60 seconds) without a queued/running semantic job. Exhausted retries and future backoff are excluded; a long active model call is not marked delayed by age alone. Four cases exercise those boundaries; all 23 unit health tests pass. The storage contract now checks exhausted and manual-retry aggregates but remains unrun without Postgres.
11. **Unclaimed exchange and FIFO health:** the reader now aggregates ready exchanges and closed exchanges behind an earlier incomplete exchange without returning message content or IDs. Ingestion health allows the five-minute idle flush plus scheduler grace before degrading an old ready backlog, and reports an old closed exchange behind a FIFO barrier even if other sessions are processing. Five health cases distinguish recent backlog, active work, and old barriers; all 28 unit health tests pass. The storage contract checks the actual admission scope and ordering but still needs Postgres execution. This aggregate scans the scoped unclaimed exchange set on each health read; production latency should be measured before adding an index or caching policy.
12. **PDF dependency recovery and model smoke:** an exhausted missing-model failure is verified as terminal (`failed`, no retry), then an explicit reindex after the dependency becomes available clears the failure and publishes readable content. The release model lane now provisions Docling layout, table, and OCR artifacts and runs an actual generated PDF through the local converter. That smoke passed locally with cached models (67 seconds); it is a model test, so ordinary fast pytest runs do not exercise it.
13. **Disabled semantic job:** a running scheduler with a registered but disabled `project_semantic` job now degrades ingestion health. Pending semantic work is marked delayed. A unit test checks the disabled-job state explicitly.

## Admission performance measurement

`server/scripts/benchmark_semantic_admission.py` uses the production selector and `cl100k_base` tokenizer with in-memory ready exchanges, a 128,000-token target, and forced flush. On this Windows machine:

| Exchanges | Exact token calls | Characters tokenized | Elapsed |
| ---: | ---: | ---: | ---: |
| 64 | 64 | 606,692 | 0.075 s |
| 128 | 128 | 2,409,815 | 0.234 s |
| 256 | 256 | 9,615,255 | 0.887 s |
| 512 | 512 | 38,427,671 | 3.649 s |

The characters processed grow about fourfold when exchanges double. The selector renders and tokenizes every growing prefix until the first exact target crossing. An incremental count cannot simply add per-exchange token counts because tokens may merge at boundaries. Any optimization must preserve the first exact crossing and test adversarial boundaries against the original implementation.

The first exact optimization groups eight full prefixes per tokenizer call and runs four tokenizer threads. The original scalar selector remains available when the LLM service lacks batch counting. With the same synthetic rows, 512 exchanges took **3.864 s scalar** versus **1.289 s batched**; both tokenized 38,427,671 characters and selected 22,528 source tokens. Four target-crossing cases with Unicode, whitespace, and header-like text matched the scalar memberships and counts. A failed batch is rechecked in order: a later disallowed token must not reject an earlier valid crossing. This lowers wall time at the cost of short CPU bursts and temporary prefix strings. It does not change quadratic total work, so a tokenizer-aware incremental design remains open for very large unclaimed backlogs. The affected semantic, LLM, and runtime suites passed 49 tests.

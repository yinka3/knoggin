# Knowledge scan notes

Read on 2026-10-08 from source and focused tests. This page covers the Knowledge side of semantic ingestion and its boundary with document indexing. It is a code review notebook, not a change proposal.

## How Knowledge is built

1. A semantic window freezes policy and moves through Episode, Context, Knowledge, and finalization checkpoints. The processor reloads the durable window after each stage (`server/src/core/ingestion/project_semantic_processor.py:268-346`).
2. Context is the canonical semantic input in SQL. `CONTEXT.md` is a guarded, user-editable projection of a revision; known stale files can be repaired, while unrecognized edits trigger conflict handling (`server/src/core/knowledge/context/projection.py:110-246`). The Context updater validates model edits and their evidence before committing a new immutable revision (`server/src/core/knowledge/context/updater.py:238-280,425-450`).
3. Knowledge reloads that exact Context checkpoint and its persisted impact blocks, supports, and frozen messages. It builds entities first, relationships second, and permits one targeted recovery pass for unknown relationship endpoints (`server/src/core/ingestion/project_semantic_processor.py:597-659`). Only current user asserted, source grounded, and human asserted blocks are extraction inputs; agent derived blocks do not feed graph extraction (`server/src/core/ingestion/batch.py:147-232`).
4. The SQL writer checks the window stage, Context revision, ownership, and impact closure again. It writes entity and relationship state, retires noncurrent observations, rebuilds the graph projection, and advances the Knowledge checkpoint inside one transaction (`server/src/core/knowledge/db/writers/semantic_commit_writer.py:90-225,235-340`). This is meant to keep the SQL facts, graph projection, and stage marker aligned.
5. Graph retrieval reads paths and hydrates their evidence; a separate endpoint expands an observation into Context blocks and leaf evidence (`server/src/core/knowledge/retrieval.py:400-453`). This is why discarded relationship supports can later affect answers and evidence trails.

## Nearby ingestion path

Generic documents are extracted into chunks, embedded, and atomically published as a search index (`server/src/core/knowledge/documents/indexer.py:103-173`). The generic document API reserves `CONTEXT.md` for the controlled Context importer (`server/src/core/knowledge/documents/service.py:1136-1142`). Source references saved with an assistant message can be passed into the later Context updater (`server/src/core/knowledge/store.py:212-249`, `server/src/core/ingestion/project_semantic_processor.py:498-513`). Document indexing does not itself run the Context entity/relationship extraction stages.

Entity merge is a separate maintenance path. `inspect_duplicate_entities` returns deterministic candidates ranked by supporting-message count. The explicit `advise_entity_merge` tool now sends bounded, user-scoped message text and episode summaries to configured `merge_model` and returns cited advice without writing a review. `propose_entity_merge` forwards selected IDs, reasoning, evidence, and an optional advisor state hash to a review service. The service rejects evidence outside the candidate pair, unresolved project Context conflicts, and stale preview hashes. A confirmed review applies a typed, state-checked global merge (`server/src/core/agent/tools/maintenance.py`; `server/src/core/knowledge/entity/merge_advisor.py`; `server/src/core/knowledge/entity/maintenance_service.py`). Scheduled preflight remains deterministic (`server/src/core/knowledge/jobs/application_maintenance_scheduler.py`).

## Defects and cascades at this boundary

- **Fixed in the current worktree: domain activation could strand a no-op window.** The Context stage now writes a zero-impact Context revision at the active window's frozen domain version when no block changes occur. The writer no-op guard compares both content hash and domain version. The 51-test focused Context/Knowledge/build-validation suite passes; a Postgres writer contract case is collected but cannot run without the database. Full failure chain and remaining integration coverage are in [handoff notes](intersection.md).
- **Domain section transition safeguards are implemented.** Activation locks the project row before the Context root, rejects removing a section with live blocks, and waits for active windows to finish. Explicit retry reopens a legacy Context checkpoint when its revision carries the wrong domain version. A clean generated projection now repairs after a section-title change even before a version-bridge window runs; a file with user edits still conflicts (`server/src/core/knowledge/context/projection.py`). The focused follow-up suite passes **181 tests**; Postgres verification remains unavailable.
- **Implemented in the current worktree: preserve independent supports and invalidate stale evidence actions.** The extractor and SQL writer now store one observation per observed label and sufficient support set. Retiring one set preserves sibling observations and their aggregate graph edge. Reclassification ignores retired observations and rejects a plan that races with retirement; open maintenance reviews that cite retiring evidence become stale in the same semantic commit transaction. A Postgres contract covers those outcomes but could not be executed because local Postgres setup did not finish. Focused unit suites pass **105 tests**, and Ruff passes for all changed Python files.
- **Fixed in the current worktree: merge ranking and review validation.** Candidate SQL ranks by support count before `LIMIT`, and `propose()` verifies supported evidence kinds and membership, preview readiness, and optional expected state hash. Unit tests cover the validation and query order; a storage contract covers a weak lower-ID pair competing with a stronger later pair but needs Postgres to execute.
- **Changed: source-only names stay unresolved.** A structured fallback candidate whose name is absent from the Context block cannot create an entity association. Its supporting message reference and exact quote are checked and kept in a transient issue. JEV skips these candidates before calling its provider. The local NLI machinery was removed because its real-world benefit had not been measured. There is no durable queue for the unresolved proposal.

## What tests establish

# Common-layer remediation

> Current verification (2026-10-19): see [verification status](verification-status.md) for the passing PostgreSQL runs, remaining coverage limits, and planned full Docling ingestion on Linux. Older database-unavailable statements below describe earlier runs.

Working record, 2026-10-11. The [common scan](common.md) and [cross-layer traces](common-intersections.md) hold the original evidence. This record tracks changes made against every numbered finding, including the compatibility cases found during implementation.

## Implemented

1. **Relationship vocabulary:** Configured names and aliases now use the same normalization as observed relationship labels. New definitions reject collisions across canonical names, labels, and aliases. Compiled snapshots give canonical names precedence when replaying an older ambiguous value. Durable project reads accept those older values so a project can open and be repaired; an unchanged ambiguous value cannot be activated again. Exact older labels retain their distinct meanings; new wording that normalizes to multiple older labels is still ambiguous. Tests cover strict candidates, legacy load, correction, and snapshot replay.
2. **Finite settings:** Spending limits, model prices, and the common-word frequency threshold now reject infinity and NaN at settings validation. Tests cover persisted settings input and finite controls. This closes the setting-level bypass; it does not measure model spending against a real provider.
3. **Domain activation:** An active runtime resolves and checks the selected VP-01 adapter before the domain store commits. The follow-up review extended the preflight to unloaded-project activation and project creation, so failed model loading leaves storage and project files untouched. Activation rejects a bad version or unavailable project before model loading, then loads before taking the manager lock and rechecks shutdown and project state before the existing store version check. Tests assert load/commit/install order and no commit on a missing or invalid adapter. Loading a heavy model can still add latency before a later valid version or Context-section conflict rejects activation.
4. **Malformed JSON diagnostics:** `safe_json_loads()` logs the error category and location without copying raw input. A Loguru sink test passes private tool-argument text and asserts it is absent from warnings.
5. **Agent Brain:** New and full Brain writes enforce the total and section limits and unique required headings. Existing oversized or duplicate stored Brains remain readable through the read tools. A section edit or restore can repair an oversized stored section because the resulting full Brain is validated before writing. Tests cover specialist creation, read paths, repair, snapshots, and rejected writes before storage.
6. **Document parser coordinates:** Source locators require finite bounding boxes. Docling projection omits invalid bounds but keeps native PDF cell text, including when one cell on an index page has unusable coordinates; its nested raw structure replaces non-finite values with `null`. The writer uses strict JSON serialization for snapshots, layouts, and embeddings before a transaction. Producer and writer tests assert clean payloads and no transaction for invalid values.
7. **Agent tool arguments:** The shared validator now enforces declared string patterns and finite numeric values. Tests use the actual entity-merge state-hash schema and relationship-conflict confidence schema.
8. **Failure-event privacy:** The coordination allowlist no longer accepts generic exception `error` or `reason` strings; the local-reference event retains its fixed reason code. Scheduler failure, preflight, timeout, monitor, and task-cleanup logs record exception types instead of message text or tracebacks. Tests capture both events and ordinary Loguru output containing a private-text exception.
9. **Older relationship prompt:** The dormant message-based relationship prompt now shows an empty result for co-location and an edge for an explicit shared action. Its offline token-fixture caller still loads it. A prompt-content check guards that distinction; this does not establish how a model will respond.

## Additional defect found while following the document path

The document embedding provider could return NaN, a malformed batch, or a malformed vector. The indexer previously checked only count and dimension, and malformed output could be treated as invalid document content. It now validates each provider batch and the complete vectors before storage and uses the bounded dependency-retry path. Tests assert the first retry, the terminal outcome after the attempt limit, and no partial publication when a later batch is malformed. The [general ingestion notes](general-ingestion.md) explain the existing retry policy.

The broad unit run also exposed an adjacent benchmark coverage defect. On Windows, the VP-01 benchmark cannot read POSIX peak RSS, yet one test required a value. Worse, a configured RSS regression gate silently passed when that metric was missing. The test now treats the metric as unavailable on Windows and the gate fails explicitly if a memory limit was configured without a measurement. This does not add Windows memory measurement.

It also exposed one real JEV rebuild defect and six stale assertions. The stale tests expected a name found only in a supporting message to become a Context entity, contrary to the established literal-in-block rule; they now assert a block-scoped unresolved issue and no JEV call. The real defect was that an exhausted observation budget prevented reconstruction of an unchanged, already accepted candidate on the second pass. A replay lane now checks prior accepted block/name/source keys before bounded new-candidate work and reuses a matching decision without another model call. Tests cover unchanged reuse behind a new earlier gap and invalidation when evidence or policy changes.

## Follow-up branch review, 2026-10-12

- **JEV replay:** More than 512 new diagnostics could hide a prior accepted candidate behind the preparation limit. Replay lookup now scans the current diagnostic names first, then spends bounded candidate checks; it also preserves the original alias-versus-diagnostic source in the request fingerprint. The regression covers an exhausted budget, 512 earlier gaps, no extra JEV call, and alias replay. This adds a linear name scan over the diagnostic list on rebuilds with accepted decisions.
- **Legacy relationship replay:** Two exact labels that an older domain could distinguish were collapsed to one normalized key. A derived exact-label lookup restores those meanings through compiled snapshot replay. Canonical names still win, including a compiled snapshot with a hyphenated canonical name. If an older snapshot repeats the same exact label, its first owner remains the fallback owner.
- **PDF pages:** Rejecting a non-finite cell box had also removed its text when other cells on an index page were valid. The text now survives without a box. Duplicate native cell text stays duplicated even if Docling markdown lists it once. A cell without coordinates is appended after positioned lines because its original order is unknown. Blank document-wide Docling markdown can now use nonempty page text for an index or ordinary PDF page; rebuilt text drops old Docling charspan offsets whose alignment is no longer known.
- **Agent Brain and tool logs:** Section edit/restore can repair the targeted invalid legacy section while still rejecting an invalid final Brain. Tool-call metadata and schema errors count unknown model-supplied argument names without copying them into logs or errors. Unexpected tool and audit failures log exception types without private exception text. Audit records remain in the scoped Postgres audit table.
- **Unloaded project model availability:** Domain activation and initial creation now load and check VP-01 before durable writes. Activation checks the project and version first, does the heavy load outside the manager maintenance lock, and checks project/shutdown state again after taking it. The existing project-create/shutdown overlap is a separate lifecycle limit. The storage transaction test's fake resources now expose VP-01 so it still reaches its intended rollback assertion.

## Coverage and remaining limits

- Targeted tests exercise the boundary where each bad value or failure enters the system, plus its next durable or runtime effect. They are stronger than tests that only assert helper return values, but they remain mostly fake-backed.
- The document writer checks use a fake transaction cursor. A real PostgreSQL `jsonb` write with a sanitized Docling snapshot has not run in this pass; the local Docker daemon is unavailable.
- Real GLiNER/VP-01 loading, hosted extraction behavior, and agent model compliance with prompt wording have not been measured here. The active-runtime activation test uses a controlled adapter loader.
- A preflight cannot guarantee a model remains available at a later bootstrap if its files or environment change after activation.
- The scan listed several common utilities with no production caller found (`safe_update`, `BackgroundTaskGroup`, `cosine_similarity`, two legacy prompt formatters, and `extend_local_id_maps`). They are cleanup candidates, not demonstrated behavior defects. This pass leaves their interfaces in place; the offline token-fixture script also keeps its own legacy prompt formatters.
- The complete server unit suite passed **2,033 tests** with **2 skips** and three dependency deprecation warnings. The three architecture checks passed. The changed fake-backed document writer contract passed in its focused run, and `ruff check src tests scripts` plus `git diff --check` passed.
- The follow-up review's combined domain, schema, Brain, and project lifecycle run passed **106 tests**. JEV candidate preparation passed isolated checks using its actual source function. Isolated PDF recovery and tool-log checks also passed. The full JEV, document extraction, tool dispatch, and real Postgres contract tests could not run in this Windows session because Application Control blocked native spaCy, pandas, or psycopg DLLs, and no local Postgres test service was available. Their regression tests are present but still need a normal test environment. Follow-up Ruff, Python syntax checks, and `git diff --check` passed.
